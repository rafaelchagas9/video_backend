# Creator enrichment service

A FastAPI service that returns external creator metadata as candidates for
manual review. The Bun backend owns accepted writes. The shared
[StashBox adapter](src/enrichment_service/sources/stashbox.py) supports ThePornDB
and StashDB; ThePornDB also uses REST for exact URL/slug/ID lookups.

## Setup and run

From this directory:

```bash
uv sync --frozen
cp .env.example .env
# Configure the selected provider's API key.
./run.sh
```

Alternatively run `uv run python -m enrichment_service.main`. The default port
is 8200. `GET /health` reports service status; FastAPI's `/docs` exposes the
request and response models for `POST /enrich`.

Configure provider credentials and switches in [.env.example](.env.example).
The source registry defaults to ThePornDB. An explicit request `sources` list
can select ThePornDB and/or StashDB when the corresponding key is configured;
see [the registry](src/enrichment_service/sources/__init__.py) for selection rules.
A response can contain candidates from one source and errors from another.

## Provider exploration

The [API reference snapshots](api-reference/README.md) are dated investigation
artifacts, not a current upstream contract. Exploration scripts make external
requests and read this directory's `.env`, falling back to the repository root.
Run them deliberately with the intended provider and query:

```bash
uv run python scripts/explore_apis.py "Example Name" --source tpdb
uv run python scripts/explore_apis.py "Example Name" --source stashdb --introspect
```

`--raw` prints full responses; `--save` writes dumps to `tmp/`. Keep personal
query results and credentials out of commits. Automated source tests use mocked
responses:

```bash
uv run python -m unittest discover -s . -p 'test_*.py' -v
```

Image search and social/platform scraping remain possible future sources; they
are not implemented adapters.

### Metadata providers, FansDB and local Stash

Provider configuration can now be managed through Kura's enrichment API. The Python
service exposes `GET /providers` and `PATCH /providers/{id}`; credentials are accepted
only on writes, persisted in `data/providers.json` with mode 0600, and never returned.
Environment values remain the defaults until a provider is updated. Set
`PROVIDER_CONFIG_PATH` to relocate the private file. Do not commit this file.

FansDB uses the current upstream `standard` Stash-box dialect. Existing StashDB
installations can retain the legacy `stashbox` search dialect; ThePornDB keeps its
GraphQL search and REST exact-ID behavior. Custom Stash-box instances use a stable
provider ID and configured GraphQL endpoint. Add your FansDB credential once the
invitation is available; no invitation or account provisioning is automated.

Configure `STASH_ENDPOINT=http://127.0.0.1:9999/graphql`, `ENABLE_STASH=true`, and
`STASH_API_KEY` if your local Stash requires one. Install the desired community
scrapers through Stash's package manager. `GET /stash/scrapers` lists the actual
installed creator and scene scrapers. An enrichment request with `scraper_url`
calls `scrapePerformerURL` for creators or `scrapeSceneURL` for videos and produces
normal reviewable suggestions. A scraped site's own ID remains provenance,
never a fabricated Stash identity. No automatic metadata acceptance occurs.

For scene identification, Kura's normal enrichment run accepts
`identify_by_hash: true`, which reads only the selected video's first and last
64 KiB to calculate Stash-compatible OSHASH. Alternatively supply a genuine
`fingerprint: {algorithm: "OSHASH"|"PHASH", hash: "16 hex characters"}` or
`stash_scene_id` to read existing fingerprints from a scene already indexed in
Stash. PHASH must be generated by Stash; no image hash is substituted for its
video fingerprint. Files that change during OSHASH calculation are rejected.

Contribution endpoints accept `{entity_type: "creator"|"scene", stash_id, source}`.
`POST /stash/contributions/prepare` reads the local Stash record and reports
missing name/title, original URL and (for scenes) pHash. Preparation makes no
mutation or external submission. `POST /stash/contributions/submit` additionally
requires `confirm: true`, rechecks readiness, and calls Stash's official
`submitStashBoxPerformerDraft` or `submitStashBoxSceneDraft` mutation. Configure
the target Stash-box endpoint and credential in **Stash itself** as well, because
Stash sends that draft. Review/publish the resulting draft on the target platform.
These endpoints use existing records in Stash; they do not automatically scan or
import your media library into that application.

The Bun backend's `DEMO_MODE=true` intercepts all of these routes: provider settings
are ephemeral, scrapers and drafts are synthetic, and enrichment operates on the
local demo proposals. No Python service, real provider or library media is accessed.
